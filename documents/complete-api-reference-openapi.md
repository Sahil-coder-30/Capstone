# Complete API Reference & OpenAPI Specification Manual

## Platform Overview
The **Taksha** platform is an AI-assisted cloud codespace and microservice ecosystem. All microservices communicate behind a Kubernetes Ingress Gateway (`k8s/ingress.yml`) using a zero-database **RS256 JWKS** security model.

The authoritative, machine-readable **OpenAPI 3.1.0** specification is maintained in:

## 🔐 Global Security Architecture

### Authentication Schemes
1. **Bearer JWT (`BearerAuth`)**:
   - Header: `Authorization: Bearer <RS256-JWT>`
   - Generated by: [`Auth/src/utils/generateTokens.js`](file:///Users/home/Desktop/Projects/Capstone/Auth/src/utils/generateTokens.js)
   - Verified by: [`Auth/src/middleware/auth.middleware.js`](file:///Users/home/Desktop/Projects/Capstone/Auth/src/middleware/auth.middleware.js) and sibling microservices using the public key from `/.well-known/jwks.json`.
2. **HTTP-Only Cookies (`CookieAuth`)**:
   - Access Token: `accessToken` (15m expiry, general API requests)
   - Refresh Token: `refreshToken` (7d expiry, scoped strictly to path `/api/auth/refresh`)
3. **Role-Based Access Control (`AdminAuth`)**:
   - Requires valid JWT where `req.user.role === 'admin'`.

## 1. Auth Service

### Discovery & Health Probes

#### `GET /.well-known/jwks.json`
- **Auth**: Public (No authentication required)
- **Description**: Exposes the RSA Public Key (`kid: auth-rsa-v1`, `alg: RS256`) in standard RFC 7517 JWKS format. All sibling microservices cache this for 24 hours.
- **Response `200 OK`**:
  ```json
  {
    "keys": [
      {
        "kty": "RSA",
        "use": "sig",
        "alg": "RS256",
        "kid": "auth-rsa-v1",
        "n": "u1w8xK... (Base64URL modulus)",
        "e": "AQAB"
      }
    ]
  }
  ```

#### `GET /api/auth/healthz` & `GET /api/auth/readyz`
- **Auth**: Public
- **Response `200 OK`**:
  ```json
  { "message": "Server is healthy" }
  ```

### Session Lifecycle

#### `GET /api/auth/google`
- **Auth**: Public
- **Description**: Redirects browser to Google OAuth 2.0 consent dialog requesting `profile` and `email` scopes.
- **Response**: `302 Found` (Redirects to Google).

#### `GET /api/auth/google/callback`
- **Auth**: Public (OAuth callback)
- **Description**: Exchanges authorization code for profile data, creates/updates `User` record in MongoDB, issues RS256 token pair, sets `refreshToken` cookie, and redirects user to `CLIENT_URL`.
- **Response**: `302 Found` (Redirects to frontend).

#### `GET /api/auth/getMe`
- **Auth**: Required (`BearerAuth` or `CookieAuth`)
- **Description**: Resolves currently authenticated user from decoded JWT `sub`/`id`.
- **Response `200 OK`**:
  ```json
  {
    "status": "success",
    "message": "User found successfully",
    "user": {
      "_id": "67cb1a2934128912ef01a901",
      "googleId": "109823719283719283719",
      "name": "Sahil Kumar",
      "email": "sahil@example.com",
      "photo": "https://lh3.googleusercontent.com/a/...",
      "createdAt": "2026-09-20T10:15:30.000Z"
    },
    "accessToken": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
  ```
- **Response `401 Unauthorized`**:
  ```json
  { "status": "error", "message": "Unauthorized: Token expired or invalid" }
  ```

#### `POST /api/auth/refresh`
- **Auth**: Cookie `refreshToken` required
- **Description**: Rotates refresh tokens and issues a new access token.
- **Security Check (Reuse Detection)**: If a previously rotated refresh token is submitted (indicating a replay attack), the entire session family is instantly destroyed from MongoDB.
- **Response `200 OK`**:
  ```json
  {
    "status": "success",
    "message": "Access token refreshed successfully",
    "accessToken": "eyJhbGciOiJSUzI1Ni..."
  }
  ```
- **Response `401 Unauthorized`**:
  ```json
  { "status": "error", "message": "Token reuse detected — all sessions revoked" }
  ```

#### `POST /api/auth/logout`
- **Auth**: Required (`BearerAuth` or `CookieAuth`)
- **Description**: Blacklists current access token in Redis and removes refresh token family from DB.
- **Response `200 OK`**:
  ```json
  { "status": "success", "message": "Logged out successfully" }
  ```

## 3. AI Orchestration Service

### Autonomous Multi-Agent LangGraph Workflows

#### `POST /api/ai/code-agent/invoke`
- **Auth**: Required
- **Format**: **Server-Sent Events (SSE)** (`Accept: text/event-stream`)
- **Request Body**:
  ```json
  {
    "message": "Add a dark mode toggle to src/components/Navbar.jsx and style it using Tailwind",
    "projectId": "67cb1a2934...",
    "sandboxId": "123e4567-e89b-12d3-a456-426614174000",
    "modelName": "mistralLarge",
    "attachments": [
      {
        "path": "src/components/Navbar.jsx",
        "content": "export default function Navbar() { ... }"
      }
    ]
  }
  ```
- **SSE Stream Sequence**:
  ```http
  event: agent:status
  data: {"phase": "queued", "title": "Preparing run", "detail": "Loading project context"}

  event: agent:model
  data: {"modelId": "mistral-large-latest", "provider": "mistral"}

  event: agent:thinking
  data: {"content": "I will examine the current Navbar implementation..."}

  event: agent:plan_created
  data: {"plan": ["Inspect Navbar.jsx", "Add theme state hook", "Write toggle button"]}

  event: agent:tool_start
  data: {"tool": "readFile", "input": {"files": "src/components/Navbar.jsx"}}

  event: agent:token
  data: {"token": "Created"}

  event: agent:done
  data: {"status": "completed"}
  ```

#### `POST /api/ai/code-agent/plan-approve`
- **Auth**: Required
- **Description**: Resumes the paused LangGraph workflow after human user approves proposed plan.
- **Request Body**:
  ```json
  {
    "projectId": "67cb1a2934...",
    "sandboxId": "123e4567-e89b-12d3-a456-426614174000"
  }
  ```
- **Response `200 OK`**: `{ "status": "success", "message": "Plan approved" }`

#### `POST /api/ai/code-agent/plan-reject`
- **Auth**: Required
- **Request Body**:
  ```json
  {
    "projectId": "67cb1a2934...",
    "sandboxId": "123e4567-e89b-12d3-a456-426614174000",
    "feedback": "Do not modify Navbar.jsx; place the toggle in Header.jsx instead."
  }
  ```
- **Response `200 OK`**: `{ "status": "success", "message": "Plan rejected" }`

#### `POST /api/ai/code-agent/stop`
- **Auth**: Required
- **Request Body**: `{ "projectId": "67cb1a2934..." }`
- **Response `200 OK`**: `{ "status": "success", "message": "Agent stopped successfully" }`

## 5. Tooling Integration Guide

### Viewing the Docs with Swagger UI
To render these documents interactively, serve `docs/openapi.yaml` via Swagger UI or Scalar:

```bash
# Using npx Scalar CLI (Zero-config instant portal)
npx @scalar/cli serve docs/openapi.yaml
```

### Auto-Generating TypeScript Client SDKs
To generate 100% type-safe Axios clients for frontend applications:

```bash
# In Frontend or payments_frontend:
npx openapi-typescript docs/openapi.yaml -o src/types/api.d.ts
```

### Importing into Postman
1. Open **Postman**.
2. Click **Import**.
3. Select [`docs/openapi.yaml`](file:///Users/home/Desktop/Projects/Capstone/docs/openapi.yaml).
4. Postman will automatically generate a collection with all 45+ endpoints, query parameters, request bodies, and environments pre-configured.
